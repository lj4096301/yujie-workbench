**版本**: v1.0-draft  
**创建日期**: 2026-09-18  
**状态**: 需求确认中  

---

## 一、产品定位

### 1.1 核心定位
一套**独立运行**的电子书深度解析工具，同时支持：
- 作为独立桌面应用使用
- 嵌入宇界工作台作为新模块（技术可行时）

### 1.2 目标用户
- 主用户：梁哥本人（深度阅读者）
- 次要用户：潜在社区用户（未来扩展）

### 1.3 核心价值
将"读完一本书"变成"掌握一本书"——通过结构化拆解，让知识可检索、可复用、可关联。

---

## 二、用户故事

### 2.1 主要场景
```
用户导入一本书
    ↓
AI自动识别书籍类型（小说/工具书/历史等）
    ↓
展示目录+前言+章节预览，用户确认分析范围
    ↓
选择分析维度（小说：人物/情节/主题；工具书：论点/方法/案例）
    ↓
AI深度解析，生成结构化笔记
    ↓
用户review质量，必要时人工修正
    ↓
导出Markdown/PDF/图片，或导入宇界知识库
```

### 2.2 辅助场景
- 快速预览：只看目录+核心论点，判断是否值得精读
- 章节精读：只对某几章进行深入分析
- 对比阅读：多本书对比同一主题
- 读书笔记管理：查看历史拆书记录

## 三、功能需求

### 3.1 输入支持

#### 3.1.1 文件格式
- **EPUB**（首选，保留目录结构）
- **PDF**（需提取文本，可能丢失格式）
- **TXT**（简单文本，无结构化信息）

#### 3.1.2 输入方式
- 拖拽文件到界面
- 文件选择器浏览
- 批量导入多本书

### 3.2 分析流程

#### 3.2.1 阶段一：元数据提取
- 书名、作者、出版社
- 目录结构解析
- 章节数量统计
- 文件大小/页数估算

#### 3.2.2 阶段二：预览确认
- 展示目录树
- 展示前言/序言全文
- 展示每章标题+首段摘要
- 用户选择：
  - [ ] 确认全部章节
  - [ ] 手动选择部分章节
  - [ ] 跳过某些章节

#### 3.2.3 阶段三：类型识别
- AI自动识别书籍类型：
  - 小说类（ fiction）
  - 工具书类（non-fiction/技能）
  - 历史/社科类
  - 其他
- 用户可手动调整类型

#### 3.2.4 阶段四：维度选择
根据书籍类型，预定义分析维度：

**小说类维度**：
- [ ] 人物关系图谱
- [ ] 情节时间线
- [ ] 主题思想提炼
- [ ] 写作手法分析
- [ ] 金句摘录

**工具书类维度**：
- [ ] 核心论点提取
- [ ] 方法论梳理
- [ ] 应用场景分析
- [ ] 案例提取
- [ ] 可执行建议清单

**历史/社科类维度**：
- [ ] 事件时间线
- [ ] 人物关系图谱
- [ ] 因果链分析
- [ ] 争议点梳理
- [ ] 观点对比

#### 3.2.5 阶段五：深度解析
- 按选定维度并行处理各章节
- 生成结构化笔记
- 质量评分（Grade A-D）
- 用户review后可修正

### 3.3 输出形式

#### 3.3.1 Markdown笔记（首选）
结构化Markdown文件，包含：
- 书籍元数据
- 核心速览
- 分维度笔记
- 引用来源标注
- 可信度评级

#### 3.3.2 PDF导出
- 打印友好的排版
- 包含图表和表格
- 适合阅读和分享

#### 3.3.3 可视化图片
- 思维导图（章节关系）
- 时间线（历史事件）
- 人物关系图
- 概念图谱

### 3.4 数据存储

#### 3.4.1 本地存储
- SQLite数据库存储：
  - 书籍元数据
  - 分析配置
  - 生成的笔记
  - 用户自定义维度
- 目录结构：
  ```
  ~/.config/bookbreaker/
  ├── data/
  │   └── books.db
  ├── books/
  │   └── <书名>/
  │       ├── raw/          # 原始解析
  │       ├── human/        # 用户可见笔记
  │       └── agent/        # 结构化数据
  └── config.json
  ```

#### 3.4.2 导出功能
- 导出为Markdown文件夹
- 导出为PDF
- 导出思维导图图片
- 支持导入Obsidian/Notion

### 3.5 与宇界知识库联动

#### 3.5.1 独立模式（默认）
- 笔记单独存储
- 手动导入到宇界知识库
- 保持数据自主权

#### 3.5.2 联动模式（可选）
- 一键导入到宇界知识库
- 自动建立双向链接
- 支持与现有笔记关联

## 四、非功能需求

### 4.1 性能要求
- 50万字书籍：10-30分钟完成解析
- 内存占用：< 2GB
- CPU占用：解析期间可接受满载

### 4.2 质量要求
- Grade A（完美）：自动通过
- Grade B（小问题）：提示后继续
- Grade C（质量问题）：需用户确认
- Grade D（严重问题）：停止并提示重新获取源

### 4.3 可用性
- 界面简洁，操作步骤清晰
- 支持中断/恢复（断点续传）
- 错误提示友好，提供解决方案

### 4.4 可扩展性
- 支持添加新的分析维度
- 支持自定义输出模板
- 支持插件化AI模型

## 五、技术架构

### 5.1 技术栈
- **前端**：React + TypeScript + Tailwind CSS
- **桌面框架**：Electron（独立运行）
- **数据库**：SQLite（better-sqlite3）
- **AI服务**：OpenAI API / Claude API
- **解析库**：自定义EPUB/PDF/TXT解析器

### 5.2 模块划分
```
src/
├── main/              # Electron主进程
│   ├── index.ts
│   └── db.ts
├── renderer/          # React渲染进程
│   ├── components/
│   │   ├── BookImport/     # 书籍导入
│   │   ├── Preview/        # 预览确认
│   │   ├── Config/         # 分析配置
│   │   ├── Progress/       # 进度显示
│   │   └── Result/         # 结果展示
│   ├── hooks/
│   │   └── useBookAnalysis.ts
│   └── pages/
│       └── BookBreaker.tsx
├── shared/            # 共享类型
└── utils/             # 工具函数
    ├── parser.ts       # 文件解析
    ├── ai.ts           # AI调用
    └── exporter.ts     # 导出功能
```

### 5.3 AI调用策略
- 流式输出，实时显示进度
- 支持API中断/恢复
- 本地缓存解析结果
- 失败自动重试（指数退避）

## 九、补充确认（2026-09-18）

### 9.1 输出格式
- **首选**：Markdown文档 + HTML可视化图片
- 不强制PDF，但保留导出选项

### 9.2 AI成本
- **策略**：先用免费API测试（如Hermes自带的Agnes）
- 后续可扩展到付费API
- 需要显示预估token消耗

### 9.3 隐私与笔记
- **书籍内容**：允许上传第三方API
- **读书笔记**：支持用户手动添加笔记，后续可汇总查看
- 笔记存储位置：本地SQLite，可选导出

### 9.4 离线支持
- **核心功能**：解析、预览、维度选择、Markdown生成
- **AI功能**：离线时降级为基础模板，不调用外部API
- 需网络时自动恢复AI分析

### 9.5 主题设计
- **默认**：浅色主题（适合白天阅读）
- **备选**：深色主题（适合夜间）
- 用户可一键切换
- 字体跟随系统默认

### 9.6 笔记管理
- 拆书完成后，自动生成读书卡片（书名、作者、评分、核心收获）
- 支持后续手动补充笔记
- 可查看历史拆书记录

## 十、小说拆书核心场景（第一优先级）

### 10.1 目标
30分钟内，把一本厚小说拆成：
- **故事脉络**：起承转合 + 关键转折点
- **人物档案**：所有主要人物的出场、事迹、闪光点、原文引用
- **关键场景**：3-5个决定命运的场景 + 原文引用
- **人物关系图**：可视化图片

### 10.2 输入
- 用户上传EPUB文件（本地解析）
- 不联网搜索，不依赖书名检索

### 10.3 输出文件
```
小说名/
├── 01-故事脉络.md      # 起承转合时间线 + 关键转折
├── 02-人物档案.md      # 每个人物：出场章节 + 关键事件 + 性格 + 原文引用
├── 03-关键场景.md      # 3-5个决定命运的场景 + 原文引用
├── 04-主题与隐喻.md    # 作者真正想表达什么
├── relations.png       # 人物关系图
└── agent/
    ├── characters.jsonl  # 人物结构化数据（方便检索）
    └── quotes.jsonl     # 带出处的原文摘录
```

### 10.4 不做的（第一阶段）
- ❌ 多书对比
- ❌ 社区分享
- ❌ 间隔重复/闪卡
- ❌ 多设备同步

### 10.5 工作流
```
用户上传EPUB
    ↓
AI解析文本结构（章节、人物名、场景标记）
    ↓
按小说维度拆解（故事线 + 人物 + 关键场景）
    ↓
生成Markdown + 关系图
    ↓
用户查看/导出
```

### 10.6 关键设计原则
1. **原文引用必须带出处**：每句话可追溯
2. **人物档案要有弧光**：不只是描述，要体现成长变化
3. **关系图是图片**：方便分享、插入笔记
4. **全自动**：不需要用户介入调整
